# 个金营销 NL2SQL 平台 v1.4 实施说明与接口数据字典

本文按照 v1.0 的“版本范围—运行配置—处理流程—数据库—API—未实现项—验收—许可”结构，记录 v1.4 的实际实现。v1.0、v1.1、v1.2、v1.3 文档作为历史版本保留；当前部署、升级、数据库结构和接口以本文及 v1.4 代码为准。项目中的客户、姓名、手机号、资产、交易和营销数据均为虚构演示数据。

## 1. 版本范围

技术栈为 JDK 17、Spring Boot 4.1.1、MyBatis-Plus 3.5.16、Maven 3.9.16、Vue 3、TypeScript、Element Plus 2.x、ECharts 6、MySQL 8.4 和单节点 Redis 7.x。JSqlParser 5.2 由 MyBatis-Plus 依赖带入。后续业务查询统一使用 MySQL，不使用 Spark SQL 或 Hive；本版不部署 Redis Cluster。Milvus 与 BCG-E3 只保留外置接口和配置，没有进入运行链路。

### 1.1 本版已实现

1. 修复饼图窄卡片外部标签被画布边界裁切的问题。宽度不足 680px 或分类超过 6 项时，不绘制容易裁切的外标签，改由图下列表完整显示分类、原始数值、单位和占比；宽图继续保留外标签和引导线。
2. 将自由 SQL 的自动修复统一为任务级额度：首次候选之外最多调用模型修复 2 次，确认、澄清和重新进入执行阶段都不会重置额度。
3. 新增三类修复触发点：模型 SQL 未通过 AST/对象/范围校验、执行时出现已知 MySQL 表达错误、成功执行后结果结构与原问题明显不一致。
4. 新增无业务值的结果结构复核。只向模型发送原问题、SQL、返回列名、列类型、返回行数、模型声明的字段角色/聚合口径和展示类型，不发送客户编号、姓名、金额等实际行值。空结果不自动判定为错误。
5. 新增 `query_sql_repair` 表，保存任务、次数、触发阶段、状态、原 SQL、脱敏失败原因、修复原因、修复后 SQL 和时间。任务状态与 SSE 同步返回 `repairs`。
6. 前端默认只显示“已自动修复 SQL（N 次）”；用户主动展开后才显示每次原因、状态和修复前后 SQL。
7. 延续并复验 JSqlParser AST 白名单校验，覆盖列、表/列别名、INNER/LEFT JOIN、CTE、派生表、相关子查询、UNION、聚合、HAVING、CASE、窗口函数、函数白名单和范围表达式；增加复杂 SQL 与权限传播参数化测试。
8. 每个修复 SQL 都重新经过单条只读限制、表/列/函数白名单、LIMIT、账号范围、已确认客户范围和风险确认。修复不能继承旧 SQL 的安全结论或确认令牌。
9. 数据库连接失败、数据库权限错误、取消和超时不触发模型修复；结果复核服务不可用时记录审计事件，但不丢弃已经安全执行的结果。

### 1.2 范围调整与设计取舍

- 根据本版最终确认，会话历史展示顺序不作修改。`GET /api/v1/conversations` 继续按 `conversation_session.created_at DESC, session_id DESC` 返回，前端继续按 `created_at` 分为今天、昨天和更早。
- “结果明显不符合问题”只判断确定性的结构偏差，例如要求分组统计却返回客户明细、缺少明确要求的指标或维度。数值大小、业务结论和空结果无法仅凭结构判断，不触发修复。
- 结果复核失败不等于 SQL 不安全。复核模型不可用时，已通过服务端校验且已成功执行的 SQL 结果仍可返回，同时记录 `QUERY_RESULT_REVIEW_UNAVAILABLE`。
- 修复原因由服务端校验器、MySQL错误分类器或结果结构复核器产生并持久化，不保存模型思考正文、原始数据库异常、API 密钥或实际查询行值。
- 两次修复均失败后，可以匹配完全覆盖原问题的固定模板；没有合适模板时返回无业务数据的降级说明，不用其他口径冒充原问题答案。

### 1.3 前端设计约定

本版使用 `frontend-design` 技能并延续 v1.3 的近白背景、细边框、中行红主操作色、系统中文字体和 Element Plus 图标。页面主任务仍是提问、补齐条件和理解查询结果，不新增无业务需求的导航入口。

- 饼图把“可读完整数值”置于装饰性外标签之前；窄布局不强行缩小文字或截断数值。
- 修复轨迹是辅助审计信息，默认折叠，不与主要回答争夺层级。
- 完整分类名称允许换行；数值和占比允许在手机宽度下换到第二行。
- 异步状态新增“复核结果结构”，并保留运行、反问、确认、成功、失败、取消、超时和降级状态。
- 尊重 `prefers-reduced-motion`；图表继续监听容器尺寸变化并重绘。

## 2. 运行与配置

### 2.1 本地启动

1. 启动 MySQL 8.4、单节点 Redis 7.x 和 Docker Desktop；本项目不要求 Redis Cluster。
2. 确认本地数据库和 Redis 密码通过被 Git 忽略的配置或环境变量提供。
3. 停止旧版本后端，再启动 v1.4。Flyway 自动执行 V1–V9；从 v1.3 升级只执行 V9。
4. 在 `crm/backend` 使用 JDK 17 和 Maven 3.9.16 启动后端。
5. 在 `crm/frontend` 使用 Node.js 20 以上版本启动 Vite。

```powershell
# 后端
cd crm/backend
$env:SPRING_PROFILES_ACTIVE = 'local'
mvn spring-boot:run

# 前端
cd crm/frontend
npm install
npm run dev
```

默认前端地址为 `http://127.0.0.1:5173`，默认后端地址为 `http://127.0.0.1:8080`。本机若使用 18080，可在 `.env.development.local` 设置 `API_PROXY_TARGET=http://127.0.0.1:18080` 并重启 Vite。

### 2.3 数据库升级

V9 只新增 `query_sql_repair`，不修改已有业务数据、会话顺序或消息内容。不要修改已经应用的 V1–V8 文件。升级前停止 v1.3 活动任务并备份数据库；前后端应部署同一版本。

```powershell
mvn test
mvn package
```

首次启动 v1.4 后可检查：

```sql
SELECT version, success FROM flyway_schema_history ORDER BY installed_rank;
SHOW CREATE TABLE query_sql_repair;
```

### 2.4 日志与敏感数据边界

- `application.log`：运行诊断，不写密钥或查询结果行。
- `conversation.log`：脱敏后的用户输入、状态和结果摘要；不保存模型思考。
- `sql-review.log`：SQL 规划、校验、执行、结果结构复核阶段及脱敏绑定参数。
- `audit_event`：修复开始、候选生成、结果不匹配、复核不可用和最终状态摘要。
- `query_sql_repair`：完整修复前后 SQL 和可公开原因；仅通过任务所有者的状态/会话接口返回。

结果结构复核摘要不包含样本行，即使业务表是模拟数据也遵守该规则。SQL 本身可能含当前账号范围或已确认客户编号，因此日志和数据库修复表仍需按内部审计数据保护。

## 3. 处理流程与关键实现

### 3.1 主流程

```text
提交问题
  → JWT确认用户与账号范围
  → 规则解析或DeepSeek生成候选计划
  → AST、对象、列、函数、LIMIT、账号/客户范围校验
      ├─ 可修复校验失败 → 最多2次修复 → 从头校验
      └─ 不可修复安全/账号配置问题 → 失败
  → 风险评估，必要时等待用户确认
  → MySQL只读执行
      ├─ 已知表达错误 → 最多2次修复 → 从头校验
      ├─ 取消/超时/连接/权限错误 → 不修复
      └─ 成功且非空 → 结果结构摘要复核
            ├─ 明显偏题 → 最多2次修复 → 从头校验
            └─ 一致/复核不可用 → 结果组装
  → 指标、图表、明细和分析
  → 会话、事件、历史、审计与修复轨迹持久化
```

### 3.2 两次安全自修复

`repair_attempts` 属于 `query_task`，所有触发类型共用。首次 SQL 不计为修复；第一次模型修复后为 1，第二次为 2。确认后恢复执行、澄清或修复后再次失败都不会把次数归零。

可修复校验码为 403102、403104、403105、422101、422102、422103、422104，分别覆盖对象/跨库、账号范围、已确认客户范围、SQL结构/表达式、LIMIT、空计划、列/别名。403103 表示账号本身未配置范围，不让模型猜测权限。

可修复 MySQL 错误只采用脱敏分类：1054 列/别名、1064 语法、1055/1140 分组、1111 聚合位置、1241/1242 子查询列/行数、1305 函数。连接、授权、锁等待、取消和超时不把原始数据库错误发送给模型。

修复提示词要求：保持原始意图；依据数据字典修正；不得扩大账号或客户范围；只返回一条完整 SELECT；优先修复表、列、别名、关联、聚合、GROUP BY、时间、函数和范围；无法安全修复时不得编造。

### 3.3 结果结构复核

非空 DeepSeek 结果进入 `RESULT_REVIEWING`。摘要示例：

```json
{
  "returned_row_count": 3,
  "columns": [
    {"name":"age_band_code","type":"TEXT"},
    {"name":"customer_count","type":"NUMBER"}
  ],
  "declared_columns": [
    {"key":"age_band_code","role":"DIMENSION","aggregation":"NONE","unit":""},
    {"key":"customer_count","role":"MEASURE","aggregation":"SUM","unit":"人"}
  ],
  "requested_display":"BAR"
}
```

摘要不含 `rows`、样本值、客户编号、姓名、金额或结果分析。复核器只返回：

```json
{"aligned":false,"reason":"用户要求按年龄段汇总，但返回结构只有客户明细列"}
```

空结果不复核，因为权限范围和业务条件可能确实没有命中数据。复核不可用时记录事件并继续组装安全结果；复核明确不一致时丢弃当前行集，不在 API 中展示，并消耗一次统一修复额度。

### 3.4 JSqlParser AST、安全与范围证明

`SqlAstValidator` 使用 JSqlParser 5.2 解析单条 SELECT。SQL 长度不超过 30000 字符，解析超时 2 秒，嵌套深度不超过 12，表达式节点不超过 3000，最外层必须有 1–100 的常量 LIMIT。

允许：非递归 CTE、派生表、相关子查询、UNION/UNION ALL、INNER/LEFT JOIN、聚合、GROUP BY、HAVING、CASE、BETWEEN、IN、EXISTS、NULL 判断、算术、日期函数、窗口函数及有限 CAST 类型。标识符必须是英文 snake_case 兼容格式。

拒绝：SELECT 星号、多语句、注释、变量、DML、DDL、锁定读取、跨库对象、递归 CTE、CROSS/NATURAL/RIGHT/FULL JOIN、命名窗口、SQL_CALC_FOUND_ROWS、危险或未知函数、模糊列、重复结果列、不在 Schema 白名单中的表/列。

权限不是字符串搜索。每个查询块、UNION 分支和物理数据源都必须能通过等值关联证明连接到当前账号的 `dim_customer.manager_id/branch_id/region_code`。OR/NOT 中的范围条件不作为授权依据，CTE 的授权不会自动传递给后续新扫描的事实表。已确认单客户查询还必须证明每个客户来源限定到同一 `customer_id`。

### 3.5 饼图显示策略

`ResultChart.vue` 通过 `ResizeObserver` 获取真实容器宽度：

- 容器宽度小于 680px 或分类超过 6 项：关闭 ECharts 外标签和引导线，避免画布裁切；图下列表显示完整分类、原值、单位和两位小数占比。
- 宽图且分类不多：保留外标签，使用 `alignTo: edge`、边距、换行宽度和重叠隐藏。
- Tooltip 始终限制在图表内；图下列表不依赖鼠标，键盘与触摸设备均可读取。
- 手机宽度下数值移动到分类名称下一行，不使用省略号隐藏关键数字。

## 5. API 详细示例与数据字典

### 5.1 通用约定

接口路径继续使用 `/api/v1`，应用版本为 1.4.0。JSON 字段为 snake_case。登录和健康检查外均要求 `Authorization: Bearer <token>`。身份和范围只取自 JWT，客户端不能提交可覆盖的 user_id、manager_id、branch_id 或 region_code。

```json
{"code":0,"message":"处理成功","data":{},"request_id":"req-001"}
```

`X-Request-ID` 可选；提交问题必须使用稳定 `Idempotency-Key`。任务状态接口即使返回 FAILED，HTTP 请求本身通常仍为 200，前端按 `data.status` 判断。

### 5.5 SSE事件

`GET /api/v1/queries/{taskId}/events`，支持 `Last-Event-ID` 和 `after_event_id`。每个 `data` 是完整 TaskStatus 快照，因此 v1.4 的 RESULT_REVIEWING 状态和 `repairs` 无需新增事件协议。服务端定期发送 keep-alive 注释；前端断线后使用最后事件号续传，失败时回退状态接口。

### 5.6 澄清、确认与取消

- `POST /api/v1/conversations/{sessionId}/messages`：提交 `task_id`、`question_id`、`answer_text` 或选项；客户定位可带 `identity_type`。
- `POST /api/v1/queries/{taskId}/confirmations`：提交 `confirm_token` 和 CONFIRM/REJECT。修复 SQL 产生新的风险计划时必须重新确认。
- `POST /api/v1/queries/{taskId}/cancel`：取消活动任务。取消和超时不会继续复核、修复或执行模板。

### 5.7 会话与消息

- `GET /api/v1/conversations?page_no=1&page_size=30`：本人未删除会话，仍按创建时间倒序。
- `GET /api/v1/conversations/{sessionId}?before_message_id=0&page_size=100`：按消息时间与编号分页并正序展示。
- `DELETE /api/v1/conversations/{sessionId}`：逻辑删除；有活动任务时返回 409007。
- `GET /api/v1/conversations/{sessionId}/anchors`：用户消息目录。
- 消息复制和编辑由前端完成；编辑会提交新任务，不覆盖历史消息。
- 助手消息反馈只允许 LIKE、DISLIKE、NONE，并校验会话所有者与终态。

## 7. 验收与注意事项

### 7.1 自动验证

默认验证不调用真实模型，也不访问 MySQL 集成库：

```powershell
pwsh -File scripts/verify-v1.4.ps1
```

显式 MySQL 测试必须使用以 `_test` 结尾的隔离库：

```powershell
pwsh -File scripts/verify-v1.4.ps1 -MysqlTests -Database pf_nl2sql_v14_test
```

真实模型测试必须显式启用、提供预算计数文件，并确认会消耗 API 额度。结果结构复核会为每个非空 DeepSeek 查询增加一次模型请求，发生偏题时还会增加最多两次修复请求。

本版新增测试覆盖：校验失败后修复、结果结构偏题后修复、摘要不含实际行值、两次共享额度、修复范围重新校验、结果复核协议、复杂 AST、权限传播、窄饼图完整数值列表和前端修复详情。

2026-08-28 本机实测结果：后端默认测试 120 项通过、17 项按设计跳过；在隔离库 `pf_nl2sql_v14_test` 上启用 MySQL 集成测试后 123 项通过、0 失败、0 跳过；前端 6 项测试通过且生产构建成功；Python 评测比较器 5 项通过。测试库已由 Flyway 验证 V1–V9，未对本地业务主库执行测试写入。

### 7.2 安全复验重点

- 使用经理账号生成缺少 `manager_id` 的 SQL，确认候选不执行，修复后必须带 M0001 且重新校验。
- 让修复模型返回 M9999，确认两次候选均被拒绝且没有进入 JDBC。
- 触发取消、超时或连接错误，确认 `repair_attempts=0`。
- 检查模型结果复核请求，只含列名、类型、行数和字段声明，不含实际行值。
- 检查 `query_sql_repair` 最多两条，且每条原因、状态和 SQL 完整。
- 在三栏和手机宽度检查饼图，确认分类、原值和占比完整可读。
