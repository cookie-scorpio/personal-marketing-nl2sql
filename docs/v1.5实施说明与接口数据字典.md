# 个金营销 NL2SQL 平台 v1.5 实施说明与接口数据字典

本文是 v1.5 的唯一现行说明，合并了 v1.4 之后的全部阶段性改动，并补充本轮客户筛选、姓名脱敏和演示数据调整。产品、前端和后端版本统一为 **1.5.0**。Flyway 的 V1–V12 是数据库迁移顺序，不随产品版本重命名。

项目只使用虚构演示数据。当前可运行系统由 Vue 3 前端、Spring Boot 后端、MySQL 8.4 和单节点 Redis 组成；模型由 Spring Boot 直接调用，不需要启动独立的大模型或数据服务。

## 1. 本次更新范围

v1.5 是从 Git v1.4 基础上的一次集中更新，主要解决查询过程不稳定、客户定位易误选、结果展示不清楚、会话管理不完整和演示数据难复现等问题。

### 1.1 已实现功能

| 功能 | 实现说明 |
|---|---|
| Agent 步骤展示 | 查询运行时按阶段展示进度和到达时间；结束后折叠为完成步骤数与总用时，失败状态在摘要中标明 |
| 会话与消息 | 持久化会话、消息、上下文和阶段事件；支持刷新恢复、连续追问、消息目录、复制、编辑重发、点赞/点踩 |
| 删除随时可用 | 删除会话时，同一事务内先取消未结束任务，再逻辑删除会话；迟到的模型或 SQL 结果不能恢复已删除会话 |
| 追问继承 | 指代词、时间条件和分组条件可继承；“全部客户”“各机构”等扩大范围表达不会错误继承单客条件 |
| 澄清浮窗 | 时间口径、展示口径和客户选择统一显示在输入框上方；推荐项排在首位，支持键盘选择和取消 |
| 客户定位 | 支持虚构完整姓名、姓氏称谓、客户编号和手机号后四位；所有定位都受当前账号数据范围限制 |
| 固定条件筛选 | 原问句中的客户条件由服务端保存并锁定，前端输入框只做附加筛选，不能修改原条件 |
| 唯一与零匹配 | 原条件匹配一位客户时显示只读“当前查询客户”卡片并自动继续，不提供候选输入框；匹配零位时直接提示未找到并结束；多结果才显示筛选列表 |
| 自动筛选 | 多结果列表打开时输入框为空，先显示原条件下全部客户；输入后 280ms 自动筛选，不需要搜索按钮；清空后恢复全部结果 |
| 筛选字段限制 | 手机尾号已确定时只能按姓名片段或编号筛选；完整姓名已确定时只能按编号或尾号筛选；姓氏已确定时可按姓名片段、编号或尾号筛选 |
| 手动确认边界 | 多结果场景中，即使附加筛选后只剩一位，也必须由用户点击客户卡片确认，避免逐字输入途中误提交 |
| 两人对比 | “王先生和李先生”按出现顺序逐位定位；提示明确写出当前正在确认“王先生”还是“李先生”，并立即展示该姓氏范围内候选；某一位原条件唯一时自动确认，同一客户不能重复选择 |
| 用户原话展示 | 用户消息气泡及会话恢复后的用户消息保留本人输入的完整姓名；助手回显、客户卡片、查询结果、日志及模型侧文本继续脱敏 |
| @客户名单 | 粘贴两个以上客户编号可折叠为名单；服务端批量校验账号范围，权限外编号必须经用户确认剔除；SQL 使用受控 `IN` 名单 |
| 姓名脱敏 | 三字姓名保留首末字，例如“王小明→王*明”；二字姓名保持“李明→李*”；已脱敏历史文本不重复加工 |
| mention 劫持修复 | “姓名和资产”“姓名和电话”等字段描述不会被误识别为客户姓名；电话、手机、号码、地址、邮箱等业务词均被排除 |
| 图表与分析 | 支持柱状图、折线图、面积图、构成图、散点图和热力图；多指标可拆图；编码值统一翻译为中文 |
| 图表口径冲突 | 明确要求饼图但问题描述时间趋势时，由后端稳定发起展示口径澄清，不依赖模型临时判断 |
| 结果表达 | 单行结果使用陈述句；两位客户结果生成高低比较句；空结果说明当前数据覆盖范围 |
| CSV 导出 | 直接导出界面已脱敏的明细行，使用 UTF-8 BOM，避免 Excel 中文乱码，不接触未脱敏数据 |
| SQL 安全 | 只允许单条只读 SQL、白名单表和受控函数；JSqlParser 检查 AST、账号范围、客户绑定和结果上限 |
| SQL 修复 | 校验失败、已知 MySQL 表达错误或结果结构偏题时最多修复两次；每个候选重新通过全部安全校验 |
| 结果结构复核 | 只向模型发送 SQL、列名、类型、行数和声明口径，不发送业务结果值；复核不可用时不丢弃已执行结果 |
| 权限与登录 | BCrypt 密码、本地三类演示账号、JWT、客户经理/团队负责人/机构负责人三级数据范围；JWT 密钥缺失时拒绝启动 |
| 稳定模拟数据 | 固定随机种子和固定基准日；交易、持仓和营销数据满足时间及金额关系；提供稳定客户锚点和演示会话重建命令 |

### 1.2 客户筛选规则

客户筛选采用“固定条件 + 附加筛选”两层规则。固定条件来自原问句，保存在当前活动任务中；`customer-search` 接口只接受附加关键词，服务端不会相信前端传来的固定条件。

| 原问句条件 | 空输入框结果 | 允许的附加筛选 |
|---|---|---|
| 手机号后四位 0697 | 当前账号范围内全部尾号 0697 客户 | 姓名任意汉字片段、客户编号 |
| 完整姓名王小明 | 当前账号范围内全部同名客户 | 客户编号、手机号后四位 |
| 王先生（姓王） | 当前账号范围内全部王姓客户 | 姓名任意汉字片段、客户编号、手机号后四位 |
| 客户编号 | 正常情况下唯一，直接继续 | 若未来存在部分编号场景，只允许其他未占用字段 |
| 没有固定条件 | 不返回全量账号范围 | 必须先输入姓名、编号或尾号 |

附加姓名采用包含匹配，因此输入“小明”或“王小明”都能命中王小明；固定完整姓名采用精确匹配；固定姓氏采用前缀匹配。多结果卡片可点击确认；唯一结果卡片只读并随查询继续。两种客户卡片都只返回脱敏姓名、客户编号、机构和虚构脱敏手机号。

## 2. 系统结构与处理流程

### 2.1 运行组件

```text
浏览器
  → Vue 3 / TypeScript / Element Plus / ECharts
  → Spring Boot 4.1.1
      ├─ 登录、JWT、会话、任务和审计
      ├─ 规则识别、客户定位、追问继承和澄清
      ├─ DeepSeek 查询计划与有限修复
      ├─ AST、账号范围、客户范围和风险校验
      └─ MySQL 查询、结果整理和脱敏
  → MySQL 8.4（业务数据、账号、会话、任务、审计）
  → Redis 7（短期幂等索引，可降级）
```

### 2.2 查询流程

```text
提交自然语言问题
  → JWT 识别账号与数据范围
  → 创建会话任务并检查幂等键
  → 判断是否为追问、名单或明确客户条件
  → 客户条件 0 人：失败结束
             1 人：显示只读客户卡片并自动确认
             多人：进入固定范围筛选浮窗
  → 规则可直接处理：生成受控计划
  → 其他问题：DeepSeek 生成结构化计划
  → 缺少时间、主题或展示口径：浮窗澄清
  → SQL AST、白名单、账号范围、客户绑定和风险检查
  → 必要时用户确认高范围查询
  → MySQL 只读执行
  → 可选结果结构复核
  → 脱敏、中文标签、指标、图表、明细与建议
  → 保存结果、消息、事件、历史与审计
```

### 2.3 任务状态

常用状态为 `RECEIVED`、`INTENT_ANALYZING`、`ASKING`、`SQL_GENERATING`、`VALIDATING`、`CONFIRMING`、`EXECUTING`、`ANALYZING`、`SUCCESS`、`DEGRADED`、`FAILED`、`CANCELLED`、`TIMEOUT`。状态使用 `state_version` 乐观锁提交，取消、删除和执行结果之间以版本号决定唯一胜者。

## 3. 安装、配置与运行

### 3.1 环境

- JDK 17
- Maven 3.9
- Node.js 20 或更高版本
- Python 3.9 或更高版本
- MySQL 8.4
- Redis 7

### 3.2 首次准备

1. 在 `deploy/local/` 复制 `.env.example` 为 `.env`，填写本地密码并执行 `docker compose up -d`。
2. 在 `crm/backend/src/main/resources/` 复制 `application-local.example.yml` 为 `application-local.yml`。
3. 配置数据库密码和至少 32 字节的 `JWT_SECRET`。
4. 启动一次 Spring Boot；Flyway 会执行 V1–V12，并创建三个演示账号。
5. 按 3.4 节重建模拟业务数据和演示会话。

### 3.3 日常启动

数据准备完成后，日常使用只需启动 Spring Boot 和前端；MySQL 与 Redis 容器保持运行即可。

```powershell
# 后端
cd crm/backend
$env:SPRING_PROFILES_ACTIVE = "local"
mvn spring-boot:run

# 另一个终端启动前端
cd crm/frontend
npm install
npm run dev
```

默认前端地址为 `http://127.0.0.1:5173`，默认后端地址为 `http://127.0.0.1:8080`。如本机使用 18080，在 `crm/frontend/.env.development.local` 设置 `API_PROXY_TARGET=http://127.0.0.1:18080`。

演示账号：

| 用户名 | 角色 | 数据范围 | 初始密码 |
|---|---|---|---|
| `manager01` | 客户经理 | M0001 | `Demo@123` |
| `leader01` | 团队负责人 | B001 | `Demo@123` |
| `director01` | 机构负责人 | EAST | `Demo@123` |

### 3.4 模拟数据与演示会话

推荐命令：

```powershell
cd scripts/mock-data
py -3.9 -m venv .venv
.\.venv\Scripts\pip.exe install -r requirements.txt
$env:MYSQL_PASSWORD = "本地应用数据库密码"
.\.venv\Scripts\python.exe generate_data.py --reset --reset-runtime --seed-demo-sessions
```

默认生成 10,000 名客户、200,000 笔交易、20,000 条持有、20 个活动、最多 30,000 条触达和 5 个演示会话。固定种子为 `20260826`，固定基准日为 `2026-08-31`。相同参数下结果保持一致。

`--reset` 清理六张业务表；`--reset-runtime` 清理会话、任务、历史、修复和审计；`--seed-demo-sessions` 为 `manager01` 写入可编辑重发的演示问题。它们不会删除账号、业务术语、Flyway 历史或表结构。完整参数和稳定客户编号见 `scripts/mock-data/README.md`。

### 3.5 模型配置

规则查询可使用 `MODEL_PROVIDER=mock`。自由问题配置：

```text
MODEL_PROVIDER=deepseek
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_API_KEY=填写密钥
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_TOOLS_ENABLED=true
DEEPSEEK_MAX_TOOL_ROUNDS=3
DEEPSEEK_RESULT_REVIEW_ENABLED=true
```

查询默认超时 60 秒、结果上限 100 行、最多 5 轮澄清、每个任务最多 2 次 SQL 修复。真实密钥不得写入 Git。

## 5. API 设计

所有业务接口使用 `/api/v1`，响应结构为：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "request_id": "请求标识"
}
```

除登录和健康检查外，均需 `Authorization: Bearer <JWT>`。

### 5.1 接口清单

| 方法与路径 | 用途 |
|---|---|
| `GET /actuator/health` | 健康检查 |
| `POST /api/v1/auth/login` | 登录并签发 JWT |
| `GET /api/v1/auth/me` | 当前用户和数据范围 |
| `POST /api/v1/queries` | 提交自然语言问题 |
| `GET /api/v1/queries/{taskId}/events` | SSE 阶段事件，支持 `Last-Event-ID` |
| `GET /api/v1/queries/{taskId}/status` | 状态、澄清、确认、修复或结果 |
| `POST /api/v1/queries/{taskId}/confirmations` | 确认或拒绝高范围查询 |
| `POST /api/v1/queries/{taskId}/cancel` | 取消任务 |
| `GET /api/v1/conversations` | 本人会话列表 |
| `GET /api/v1/conversations/{sessionId}` | 会话详情与消息分页 |
| `DELETE /api/v1/conversations/{sessionId}` | 级联取消活动任务后删除会话 |
| `POST /api/v1/conversations/{sessionId}/messages` | 提交澄清答案 |
| `GET /api/v1/conversations/{sessionId}/customer-search` | 当前固定条件内附加筛选客户 |
| `GET /api/v1/conversations/{sessionId}/anchors` | 用户问题目录 |
| `POST /api/v1/conversations/{sessionId}/messages/{messageId}/feedback` | 点赞、点踩或取消评价 |

### 5.2 提交问题

请求需要稳定的 `Idempotency-Key`：

```json
{
  "session_id": "8b72d9fa-9d45-4ce8-9ec4-a8c13c3ea4c5",
  "query_text": "对比王先生和李先生的资产谁更多",
  "preferred_display": "AUTO",
  "thinking_enabled": true,
  "customer_ids": []
}
```

响应返回 `task_id`、`session_id`、初始状态、进度和状态地址。相同用户、相同幂等键、相同请求内容返回同一任务；同一键对应不同内容返回冲突。任务状态中的 `resolved_customer` 可空；明确条件唯一命中后返回只读客户卡片，字段为 `customer_id`、脱敏 `name`、`branch_id` 和脱敏 `mobile`，前端不据此要求用户再次确认。

### 5.3 客户筛选接口

```http
GET /api/v1/conversations/{sessionId}/customer-search?keyword=小明&page_no=1&page_size=20
```

`keyword` 只表示附加筛选。固定姓名、姓氏、编号和尾号从活动任务的 `question_json` 读取，前端不能传入或覆盖。空关键词只在存在固定条件时合法。

```json
{
  "total": 2,
  "page_no": 1,
  "page_size": 20,
  "items": [
    {
      "customer_id": "C00000697",
      "name": "王*明",
      "branch_id": "B001",
      "mobile": "900****0697"
    }
  ]
}
```

接口使用当前 JWT 的经理、机构或区域范围。用户最终点击客户后，澄清提交接口会再次验证所选编号仍符合固定条件，不能通过手工构造请求越过筛选范围。

### 5.4 澄清对象

主要字段：

| 字段 | 说明 |
|---|---|
| `question_id` | 当前问题唯一标识，回答时必须原样提交 |
| `type` | 澄清类型 |
| `prompt` | 浮窗提示 |
| `options` | 口径选项 |
| `recognized_slots` | 服务端识别信息；客户固定条件和允许筛选类型保存在此 |
| `recommended_option` | 推荐项，可空 |
| `candidates` | 兼容字段，现行客户列表由分页接口返回 |

客户相关类型包括 `CUSTOMER_IDENTITY`、`CUSTOMER_SELECTION`、`CUSTOMER_CONFIRM` 和 `CUSTOMER_SCOPE`；其他类型包括时间、主题、冲突、展示口径和模型澄清。

### 5.5 结果对象

`QueryResult` 主要包含：

- `result_type`：指标、图表、表格或组合结果；
- `title`、`summary`：用户可读标题和摘要；
- `metrics`：指标值、单位和说明；
- `columns`、`rows`：已脱敏、已翻译的明细；
- `charts`：图表类型、维度、系列和数据；
- `analysis`：概览、洞察和下一步建议；
- `sql_preview`：受控 SQL 预览；
- `fallback`：降级原因和是否仍有可用数据；
- `repairs`：最多两次修复轨迹。

### 5.6 常用错误

| HTTP | 场景 |
|---|---|
| 400 | 输入格式、澄清答案或筛选字段无效 |
| 401 | 未登录、JWT 无效或过期 |
| 403 | 账号数据范围、SQL 范围或权限校验失败 |
| 404 | 会话、任务、客户或历史不存在/不属于当前用户 |
| 409 | 状态并发变化、幂等冲突、重复客户或问题已失效 |
| 429 | 模型调用预算或频率限制 |
| 502 | 模型、数据库或下游查询不可用 |

OpenAPI 详细结构以 `contracts/openapi/crm-nl2sql-mvp-v1.yaml` 为准。

### 7.2 从 v1.4 升级

1. 备份数据库和外部配置，停止旧前后端。
2. 部署 v1.5 Spring Boot，显式提供 `JWT_SECRET`，由 Flyway 补齐 V9–V12 中尚未执行的迁移。
3. 同步部署 v1.5 前端。
4. 若要采用新的稳定模拟数据，执行 `generate_data.py --reset --reset-runtime --seed-demo-sessions`。该操作会清空演示业务数据和运行时会话，不适用于生产库。
5. 启动前端，使用 `manager01` 检查 5 个演示会话，并重新发送其中问题完成演示验收。

### 7.3 部署注意事项

- 生产环境必须更换演示账号、密码、JWT 密钥和数据库账号。
- 后端数据库账号应只具备所需权限；业务查询建议使用独立只读账号。
- 静态服务器将 `/api` 和健康检查反向代理到后端；SSE 关闭缓冲，读取超时大于 60 秒。
- 应用、对话和 SQL 复核日志按权限保存，不记录完整模型思考和业务结果明细。
- Redis 不可用时幂等仍由 MySQL 唯一约束保证，但应监控降级状态。
