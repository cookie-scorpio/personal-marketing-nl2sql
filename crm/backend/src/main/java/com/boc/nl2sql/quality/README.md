# F 模块说明

`quality` 是 F（审计、反馈与效果评价）在后端的独立目录。它接收各业务模块已经发生的事实，保存可追溯证据，并提供后续监控和评测所需的数据基础。它不判断查询是否继续、不决定是否修复 SQL，也不改变 C 的任务状态。

## 第一阶段包含的内容

- `event`：统一事实类型、事件信息和版本。
- `collection`：业务模块提交事实的入口；保存会话、模型调用和 SQL 尝试的详细数据，同时保留原有诊断日志。
- `persistence`：写入 `audit_event`，维护 SQL 修复查询投影；数据库暂时不可用时写入本地 JSONL 文件并定时重放。
- `feedback`：保存每次反馈变化，并维护用户当前的点赞、点踩或取消反馈状态。
- `query`、`api`：按任务读取事实时间线，供质量管理员验证和后续监控页面使用。
- `config`：F 专用异步执行器和补偿任务配置。

正式事实以数据库为准，日志只用于辅助诊断。事实记录只追加、不随用户删除会话或历史而删除，当前不设置自动过期时间。除密码、API Key、Authorization 等认证凭据外，F 保存业务模块提交的完整内容，不在 F 内做数据脱敏。

## 接口与权限

- `GET /api/v1/quality/tasks/{taskId}/events`：读取任务事实时间线，支持 `after_id` 和 `page_size`。
- `GET /actuator/metrics` 及其子路径：读取连续指标。

以上接口只允许 `QUALITY_ADMIN` 访问。该角色不能访问普通查询、会话等业务 API，也没有业务数据查询范围。

## 当前指标

- 事实接收、入库失败、补偿写入和补偿重放数量。
- 模型调用耗时，按提供方、用途和成功状态区分。
- SQL 尝试数量，按处理阶段区分。
- 各事实类型的接收和成功入库数量，可用于统计任务终态、反馈和异常趋势。

## 暂不包含

第一阶段只为评测保留候选标记，点踩和异常样例先进入候选池。正式评测数据集、不可变数据集版本、手动评测运行、结果汇总和管理员前端页面将在后续阶段实现；自动评测暂不考虑。
