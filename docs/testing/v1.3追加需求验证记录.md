## 旧版回答恢复

V8 在隔离库中重复执行回填逻辑：同一旧任务只生成一条 `ASSISTANT` 消息，原有 `result_json` 的人数 42 保持不变；没有完整结果的旧任务明确显示“仅恢复已保存的状态或摘要”，不伪造数据。补入的旧助手消息按任务时间与用户消息交错显示。已删除会话不会恢复，其他账号读取返回 404001。迁移只恢复保存内容，不调用模型、不重跑历史 SQL、不开放旧确认或取消动作。

浏览器夹具“旧版回复兼容验收（模拟）”确认旧标题、摘要、表格 42 人、复制回答、回答时间和点赞/点踩按钮均可见；缺少日期/来源时显示“旧版未记录”，旧 TABLE 结果默认打开“数据明细”。

## 顺序与账号隔离

集成测试构造了 `created_at` 较早但 `updated_at` 较新的会话，以及另一个账号的会话：列表始终按 `created_at DESC, session_id DESC`，切换读取账号后顺序不变，其他账号记录不出现。详情和导航游标采用 `(created_at, message_id)` 复合顺序，跨会话游标被拒绝。前端使用固定账号存储键；账号或标签页切换会清空旧内容，迟到请求（成功和 401）不能污染新令牌。

浏览器确认客户经理登录后不显示机构负责人的兼容夹具；切回负责人账号后原列表顺序保持一致。删除操作未在浏览器中实际执行，删除权限、逻辑删除和审计由集成测试覆盖。

## 消息操作与评价

用户消息下方可见 `HH:mm`、复制和编辑图标。编辑将原文本放入输入框并显示“原记录保留”，提交后新增用户消息和任务，原消息及原回答仍在会话中。助手消息下方可见复制、点赞、点踩和回复时间。复制内容由标题、摘要、指标、分析、建议、表格明细和 SQL 预览组成；旧结果缺少新字段时只补空容器。

后端测试覆盖 LIKE → DISLIKE → NONE 的互斥与可撤销流程，评价刷新后仍可读；USER 消息、其他账号、删除后会话和生成中的回复分别被拒绝。评价只更新 `feedback_code` 与 `feedback_updated_at`，不改变消息时间、会话创建顺序，不调用模型或查询业务数据。

## 饼图与分辨率

桌面和 390×844 窄屏均检查十档存款饼图：完整 HTML 图例包含 `0-100万` 至 `900-1000万` 共 10 项、人数和两位小数占比，长名称可换行，页面无水平溢出，DOM 中没有被截断的分类名称。窄屏时画布外侧标签收起，数据仍可从完整图例和“数据明细”查看；容器尺寸变化由 ResizeObserver 触发重绘。不同浏览器字体渲染仍可能有细微差异。
