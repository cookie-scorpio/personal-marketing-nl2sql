# 个金营销 NL2SQL 平台 v1.6 实施说明与接口数据字典

本文是 v1.6 的现行实施说明，承接 v1.5 的查询、会话、客户筛选和结果展示能力，集中说明本轮工号注册、多角色授权、身份切换与管理入口改造。数据库迁移仍以 Flyway 的 V1–V17 顺序为准，不能按产品版本重命名或修改已发布迁移。

项目只使用虚构演示数据。当前可运行系统由 Vue 3 前端、Spring Boot 后端、MySQL 8.4 和单节点 Redis 组成；模型由 Spring Boot 直接调用，不需要启动独立的大模型或数据服务。

## 1. 本次更新范围

v1.6 将原先登录页选择三级业务角色的方式，调整为由后端按账号授权决定当前身份与数据范围。系统支持一个账号持有多个角色，但一次登录或切换后只以一个当前身份工作。

### 1.1 已实现功能

| 功能 | 实现说明 |
|---|---|
| 登录去除角色选择 | 登录页只保留用户名和密码。后端读取账号的有效授权，决定默认身份、可切换身份和客户经理数据范围，前端不再传递或相信角色选择。 |
| 五位工号注册 | 注册页的姓名字段改为工号；工号必须是唯一的五位阿拉伯数字。注册请求不接收角色、机构、客户经理或数据范围。 |
| 待审批账号 | 公开注册只创建待审批账号，不能直接登录。权限管理员在权限管理页授予至少一个角色后，账号启用并可登录。 |
| 三类可授权角色 | `CUSTOMER_MANAGER`、`QUALITY_AUDITOR`、`PERMISSION_ADMIN` 分别对应客户经理类、质量审计员类和权限管理员类，可组合授予同一账号。 |
| 客户经理三级范围 | 客户经理身份使用 `CUSTOMER_MANAGER`、`TEAM_LEAD`、`ORG_MANAGER` 三个业务数据范围；分别按经理、机构和区域限制业务查询。三级范围不是三个独立登录角色。 |
| 身份切换 | 左下角身份信息仅在账号具有两个及以上有效角色时显示下拉切换。切换必须经后端再次校验；返回新 JWT 后销毁并重建当前身份工作区，但不触发浏览器整页跳转。只有单一身份的用户没有切换入口。 |
| 当前身份展示 | 工作台问候、左下角身份名称和功能入口均随当前身份变化，例如“客户经理”“质量审计员”“权限管理员”。 |
| 会话身份隔离 | 会话以“用户 + 当前身份”隔离。客户经理身份创建的会话不会出现在同一账号的质量审计员或权限管理员身份下，反之亦然。 |
| 质量审计员入口 | 质量审计员的顶栏提供“智能问数 / 后台管理”下拉入口；智能问数可正常创建审计身份会话，后台管理当前为保留扩展位的空页面。 |
| 权限管理员入口 | 权限管理员的顶栏提供“权限管理”下拉入口，可查看账号、工号、状态、已授予角色和业务范围，并保存新的授权配置。 |
| 权限最小化 | 客户经理和质量审计员当前身份可以调用业务查询和会话接口；权限管理员不能调用业务查询，权限管理接口仅接受权限管理员当前身份。 |
| 旧数据兼容 | 原有客户经理、团队负责人、机构负责人和质量管理员账号在 V17 中迁移为新的授权记录；旧 JWT 缺少显式范围时，后端仍按其旧角色恢复原有业务范围。 |
| 原有能力保持 | v1.5 的自然语言查询、澄清、客户定位、名单、图表、结果分析、会话消息、反馈、SQL 安全与导出能力保持不变。 |

### 1.2 角色与功能范围

| 当前身份 | 可用页面与接口 | 业务数据范围 | 可切换条件 |
|---|---|---|---|
| 客户经理类 | 智能问数、会话历史、自然语言查询、客户筛选和结果导出 | 必填，按客户经理/团队负责人/机构负责人三级范围计算 | 同一账号另有质量审计员或权限管理员有效授权时可切换 |
| 质量审计员类 | 智能问数、独立会话历史、顶栏“后台管理”空页面 | 全部在册客户；SQL 仍强制包含 `status_code='ACTIVE'` 范围谓词 | 同一账号另有客户经理或权限管理员有效授权时可切换 |
| 权限管理员类 | 顶栏“权限管理”页面与授权接口 | 不提供业务查询范围 | 同一账号另有客户经理或质量审计员有效授权时可切换 |

角色集合与当前身份均由后端 `sys_user_role_grant` 记录确定。前端仅根据登录响应中的 `available_roles` 控制可见入口，不能通过构造前端参数取得未授权身份或数据范围。

## 2. 系统结构与处理流程

### 2.1 运行组件

```text
浏览器
  → Vue 3 / TypeScript / Element Plus / ECharts
      ├─ 登录、工号注册、身份下拉与工作台
      ├─ 质量审计员智能问数与后台管理占位页
      └─ 权限管理员账号授权页
  → Spring Boot 4.1.1
      ├─ 密码加密传输、登录、JWT 与身份切换
      ├─ 角色授权、客户经理数据范围与权限校验
      ├─ 会话、消息、任务、审计与按身份隔离
      ├─ 规则识别、客户定位、澄清和查询计划
      ├─ SQL AST、账号范围、客户范围与风险校验
      └─ MySQL 查询、结果整理和脱敏
  → MySQL 8.4（业务数据、账号、授权、会话、任务、审计）
  → Redis 7（短期幂等索引，可降级）
```

### 2.2 登录、授权与身份切换流程

```text
注册：提交五位唯一工号、用户名和密码
  → 创建 PENDING 账号
  → 权限管理员授予角色；若包含客户经理身份，同时设置业务范围与区域/机构/经理边界
  → 账号启用

登录：验证用户名和密码
  → 读取有效角色授权
  → 后端确定默认当前身份与数据范围
  → 签发携带 current role、available roles 和范围的 JWT
  → 前端进入匹配当前身份的工作台

身份切换：请求目标身份
  → 后端确认目标身份属于该账号的有效授权
  → 重新加载账号范围并签发新 JWT
  → 前端销毁上一身份的 SSE、草稿和页面暂存，在当前页面重建工作区
  → 会话列表只显示“当前用户 + 当前身份”的历史
```

### 2.3 智能问数流程

```text
客户经理或质量审计员身份提交自然语言问题
  → JWT 识别账号、当前身份和业务数据范围
  → 客户经理按三级授权范围查询；质量审计员限定全部在册客户
  → 创建同身份会话任务并检查幂等键
  → 判断追问、名单或明确客户条件
  → 澄清缺失条件，生成受控查询计划
  → SQL AST、账号范围、客户范围和风险校验
  → MySQL 只读执行
  → 脱敏、中文标签、指标、图表、分析与建议
  → 保存同身份的任务、消息、事件、历史与审计
```

质量审计员调用上述业务接口时使用独立的审计身份会话，并强制限定为全部在册客户；权限管理员调用业务接口时服务端仍返回 403。

## 3. 安装、配置与运行

### 3.1 环境

- JDK 17
- Maven 3.9
- Node.js 20 或更高版本
- Python 3.9 或更高版本
- MySQL 8.4
- Redis 7

### 3.2 首次准备

1. 在 `deploy/local/` 复制 `.env.example` 为 `.env`，填写本地密码并执行 `docker compose up -d`。
2. 在 `crm/backend/src/main/resources/` 复制 `application-local.example.yml` 为 `application-local.yml`。
3. 配置数据库密码和至少 32 字节的 `JWT_SECRET`。
4. 启动一次 Spring Boot；Flyway 会按顺序执行 V1–V17，并创建演示账号与其授权记录。
5. 按 3.4 节重建模拟业务数据和演示会话。

### 3.3 日常启动

```powershell
# 后端
cd crm/backend
$env:SPRING_PROFILES_ACTIVE = "local"
mvn spring-boot:run

# 另一个终端启动前端
cd crm/frontend
npm install
npm run dev
```

默认前端地址为 `http://127.0.0.1:5173`，默认后端地址为 `http://127.0.0.1:8080`。如本机使用 18080，在 `crm/frontend/.env.development.local` 设置 `API_PROXY_TARGET=http://127.0.0.1:18080`。

演示账号：

| 用户名 | 工号 | 已授予身份 | 客户经理业务范围 | 初始密码 |
|---|---|---|---|---|
| `manager01` | `10001` | 客户经理类 | 经理 `M0001` | `Demo@123` |
| `leader01` | `10002` | 客户经理类 | 机构 `B001` | `Demo@123` |
| `director01` | `10003` | 客户经理类、质量审计员类 | 区域 `EAST` | `Demo@123` |
| `quality01` | `10004` | 质量审计员类 | 无 | `Demo@123` |
| `admin01` | `10005` | 权限管理员类 | 无 | `Demo@123` |

`director01` 用于验收双身份切换；`quality01` 和 `admin01` 用于验收各自的独立管理入口。生产部署必须删除或替换全部演示账号与密码。

### 3.4 模拟数据与演示会话

```powershell
cd scripts/mock-data
py -3.9 -m venv .venv
.\.venv\Scripts\pip.exe install -r requirements.txt
$env:MYSQL_PASSWORD = "本地应用数据库密码"
.\.venv\Scripts\python.exe generate_data.py --reset --reset-runtime --seed-demo-sessions
```

默认生成 10,000 名客户、200,000 笔交易、20,000 条持有、20 个活动、最多 30,000 条触达和 5 个演示会话。`--reset-runtime` 会清理会话、任务、历史、修复和审计，不会删除账号、角色授权、Flyway 历史或表结构。

### 3.5 模型配置

规则查询可使用 `MODEL_PROVIDER=mock`。自由问题可配置：

```text
MODEL_PROVIDER=deepseek
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_API_KEY=填写密钥
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_TOOLS_ENABLED=true
DEEPSEEK_MAX_TOOL_ROUNDS=3
DEEPSEEK_RESULT_REVIEW_ENABLED=true
```

真实密钥不得写入 Git。查询默认超时 60 秒、结果上限 100 行、最多 5 轮澄清、每个任务最多 2 次 SQL 修复。

## 4. 数据库设计

当前共有 16 张业务与平台表。所有表由 Flyway 管理，字符集为 `utf8mb4`。

### 4.1 表清单

| 表 | 用途 | 关键字段与约束 |
|---|---|---|
| `sys_user_account` | 登录账号 | `id` 主键；`username`、五位 `employee_no` 唯一；BCrypt `password_hash`；`account_status`；区域/机构/经理边界 |
| `sys_user_role_grant` | 多角色授权 | `user_id + role_code` 唯一；`role_code` 为三类角色；客户经理授权必须带 `business_scope_level`；记录授权人、启用状态与时间 |
| `dim_customer_manager` | 客户经理维表 | `manager_id` 主键；机构、区域和状态 |
| `dim_customer` | 客户画像快照 | `customer_id` 主键；虚构姓名、脱敏姓名、手机号占位、等级、风险、资产、快照日；经理/机构/区域/资产索引 |
| `fct_transaction` | 客户交易事实 | `transaction_id` 主键；客户、产品、时间、类型、借贷方向、金额、状态；客户+日期、日期+类型索引 |
| `dim_marketing_campaign` | 营销活动 | 活动类型、状态、目标客群、渠道、归属、时间、预算和目标数 |
| `fct_product_holding` | 产品持有快照 | 客户+产品+快照唯一；持有金额、市值、收益、到期日、风险等级 |
| `fct_customer_marketing` | 营销触达与转化 | 活动+客户唯一；触达时间、渠道、响应、转化和金额 |
| `business_term` | 业务术语 | 术语编码+版本唯一；同义词、定义和映射对象 |
| `query_task` | 异步查询任务 | 问句、状态、澄清、SQL、结果、错误、客户定位、分页、幂等和状态版本 |
| `audit_event` | 不可变审计事实 | 事件标识、来源、关联会话/消息/任务、发生时间与 JSON 载荷 |
| `conversation_session` | 会话 | 用户、`identity_role_code`、标题、活动任务、上下文、状态版本、逻辑删除时间；同用户不同身份互不可见 |
| `conversation_message` | 消息 | 会话、任务、角色、业务幂等键、内容、任务快照、反馈和时间 |
| `query_task_event` | SSE 阶段事件 | 任务+状态版本唯一；事件快照和时间 |
| `query_sql_repair` | SQL 修复轨迹 | 任务+修复次数唯一；触发阶段、失败原因、修复原因和前后 SQL |
| `quality_feedback_current` | 当前质量反馈投影 | `message_id` 主键；会话、任务、用户、反馈、原因、评语和版本；完整历史仍写入审计事件 |

### 4.2 多角色与会话关键字段

| 表.字段 | 类型 | 说明 |
|---|---|---|
| `sys_user_account.employee_no` | char(5) | 注册工号；只允许五位数字；全局唯一。 |
| `sys_user_account.account_status` | varchar(16) | 账号状态；公开注册后为 `PENDING`，授予角色后启用。 |
| `sys_user_role_grant.role_code` | varchar(32) | `CUSTOMER_MANAGER`、`QUALITY_AUDITOR` 或 `PERMISSION_ADMIN`。 |
| `sys_user_role_grant.business_scope_level` | varchar(32) | 仅客户经理授权使用：`CUSTOMER_MANAGER`、`TEAM_LEAD` 或 `ORG_MANAGER`。 |
| `sys_user_role_grant.granted_by_user_id` | bigint | 最后授予或变更该账号授权的权限管理员。 |
| `conversation_session.identity_role_code` | varchar(32) | 会话所属当前身份。列表、详情、创建、删除和消息访问均用该字段与当前 JWT 校验。 |
| `query_task.user_id` / `session_id` | bigint / varchar | 任务仍通过所属会话间接继承身份隔离，不能跨身份读取。 |

### 4.3 迁移顺序

| 迁移 | 内容 |
|---|---|
| V1–V12 | v1.5 之前的账号、业务数据、查询任务、会话、消息、事件、客户名单与两人对比基础能力。 |
| V13 | `query_task` 增加分页参数。 |
| V14 | 账号增加 `account_status`，支持待审批注册。 |
| V15 | 审计事件升级为统一事实表，新增 `quality_feedback_current` 当前反馈投影。 |
| V16 | 移除不再维护的 `query_history` 兼容投影，会话与消息成为唯一历史入口。 |
| V17 | 账号增加唯一工号；新增 `sys_user_role_grant`；旧三级业务角色与质量管理员迁移为新授权；会话增加 `identity_role_code` 和可见性索引。 |

升级只能增加后续迁移。不要修改、合并、重命名或用 Flyway repair 掩盖已执行的迁移文件。

## 5. API 设计

所有业务接口使用 `/api/v1`，响应结构为：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "request_id": "请求标识"
}
```

除公开密钥、注册、登录和健康检查外，均需 `Authorization: Bearer <JWT>`。后端从 JWT 和授权记录判断当前身份，客户端不得提交数据范围。

### 5.1 接口清单

| 方法与路径 | 当前身份要求 | 用途 |
|---|---|---|
| `GET /actuator/health` | 无 | 健康检查 |
| `GET /api/v1/auth/public-key` | 无 | 获取密码加密用 SPKI 公钥 |
| `POST /api/v1/auth/register` | 无 | 用工号、用户名和加密密码提交注册申请 |
| `POST /api/v1/auth/login` | 无 | 登录并签发包含当前身份与可用身份的 JWT |
| `GET /api/v1/auth/me` | 已登录 | 获取当前 JWT 中的用户、当前身份和可切换身份 |
| `POST /api/v1/auth/switch-identity` | 已登录且持有目标身份 | 后端校验并切换当前身份，返回新的 JWT |
| `GET /api/v1/permission-admin/accounts` | 权限管理员 | 获取账号及其授权配置 |
| `PUT /api/v1/permission-admin/accounts/{accountId}/permissions` | 权限管理员 | 覆盖指定账号的角色集合与客户经理范围 |
| `POST /api/v1/queries` | 客户经理或质量审计员当前身份 | 提交自然语言问题 |
| `GET /api/v1/queries/{taskId}/events` | 客户经理或质量审计员当前身份 | SSE 阶段事件，支持 `Last-Event-ID` |
| `GET /api/v1/queries/{taskId}/status` | 客户经理或质量审计员当前身份 | 查询状态、澄清、确认、修复或结果 |
| `POST /api/v1/queries/{taskId}/confirmations` | 客户经理或质量审计员当前身份 | 确认或拒绝高范围查询 |
| `POST /api/v1/queries/{taskId}/cancel` | 客户经理或质量审计员当前身份 | 取消任务 |
| `GET /api/v1/conversations` | 客户经理或质量审计员当前身份 | 当前用户、当前身份下的会话列表 |
| `GET /api/v1/conversations/{sessionId}` | 客户经理或质量审计员当前身份 | 当前身份可见会话的详情与消息分页 |
| `DELETE /api/v1/conversations/{sessionId}` | 客户经理或质量审计员当前身份 | 取消活动任务后逻辑删除当前身份会话 |
| `POST /api/v1/conversations/{sessionId}/messages` | 客户经理或质量审计员当前身份 | 提交澄清答案 |
| `GET /api/v1/conversations/{sessionId}/customer-search` | 客户经理或质量审计员当前身份 | 当前固定条件内附加筛选客户 |
| `GET /api/v1/conversations/{sessionId}/anchors` | 客户经理或质量审计员当前身份 | 用户问题目录 |
| `POST /api/v1/conversations/{sessionId}/messages/{messageId}/feedback` | 客户经理或质量审计员当前身份 | 点赞、点踩或取消评价 |

质量审计员的“后台管理”目前是前端空页，尚未对应新增业务 API。

### 5.2 注册、登录与当前用户对象

注册请求不包含姓名和角色：

```json
{
  "employee_no": "12345",
  "username": "newuser01",
  "password": {
    "key_id": "当前公钥标识",
    "encrypted_password": "使用公开密钥加密后的密码"
  }
}
```

其中 `employee_no` 必须匹配 `^[0-9]{5}$`，且数据库中不存在相同工号。成功响应包含 `username`、`employee_no`、`account_status` 和待授权提示。

登录与身份切换都返回同一结构：

```json
{
  "access_token": "JWT",
  "token_type": "Bearer",
  "expires_in": 3600,
  "user": {
    "user_id": 3,
    "username": "director01",
    "employee_no": "10003",
    "role": "CUSTOMER_MANAGER",
    "business_scope_level": "ORG_MANAGER",
    "available_roles": ["CUSTOMER_MANAGER", "QUALITY_AUDITOR"],
    "region_code": "EAST",
    "branch_id": null,
    "manager_id": null
  }
}
```

`role` 是当前身份；`available_roles` 是该账号可切换的有效角色集合；`business_scope_level` 仅在客户经理当前身份下有效。字段使用全局 snake case 序列化。

### 5.3 切换身份

```http
POST /api/v1/auth/switch-identity
Authorization: Bearer <当前JWT>
Content-Type: application/json
```

```json
{
  "role": "QUALITY_AUDITOR"
}
```

目标角色不属于该账号有效授权时返回 403。成功后客户端必须替换旧 JWT 并刷新工作区，不能继续使用上一身份的内存会话、任务或展示数据。

### 5.4 权限管理接口

获取账号：

```http
GET /api/v1/permission-admin/accounts
Authorization: Bearer <权限管理员JWT>
```

更新授权：

```http
PUT /api/v1/permission-admin/accounts/12/permissions
Authorization: Bearer <权限管理员JWT>
Content-Type: application/json
```

```json
{
  "roles": ["CUSTOMER_MANAGER", "QUALITY_AUDITOR"],
  "business_scope_level": "TEAM_LEAD",
  "region_code": "EAST",
  "branch_id": "B001",
  "manager_id": null
}
```

规则如下：

| 授权包含内容 | 必填范围字段 |
|---|---|
| 仅质量审计员或权限管理员 | 不填写业务范围、区域、机构、经理 |
| 客户经理 + `CUSTOMER_MANAGER` | `region_code`、`branch_id`、`manager_id` |
| 客户经理 + `TEAM_LEAD` | `region_code`、`branch_id` |
| 客户经理 + `ORG_MANAGER` | `region_code` |

保存后，账号的角色授权由该请求整体覆盖。下次登录或身份切换即使用新授权；正在使用的旧 JWT 仍按其短期有效期与服务端接口校验规则处理。

### 5.5 查询、客户筛选与结果对象

客户经理身份的查询请求、稳定幂等键、客户筛选、澄清对象和 `QueryResult` 字段延续 v1.5：服务端保存固定客户条件，前端只提交附加筛选；SQL 必须通过 AST、账号范围和客户范围校验；返回数据完成脱敏、中文标签、指标、图表和分析后再写入当前身份会话。

同一账号使用不同身份访问会话 ID 时，服务端按不存在处理并返回 404，避免暴露另一身份的会话标题、消息或任务状态。

### 5.6 常用错误

| HTTP | 场景 |
|---|---|
| 400 | 工号不是五位数字、注册/授权字段无效、澄清答案或筛选字段无效 |
| 401 | 未登录、JWT 无效或过期 |
| 403 | 切换到未授予身份、权限管理员调用业务接口、非权限管理员调用授权接口、数据范围或 SQL 范围校验失败 |
| 404 | 当前身份下不存在会话、任务、客户或历史；也用于隐藏其他身份会话 |
| 409 | 工号或用户名重复、状态并发变化、幂等冲突、重复客户或问题已失效 |
| 429 | 模型调用预算或频率限制 |
| 502 | 模型、数据库或下游查询不可用 |

OpenAPI 详细结构以 `contracts/openapi/crm-nl2sql-mvp-v1.yaml` 为准。

### 7.3 部署注意事项

- 生产环境必须更换演示账号、密码、JWT 密钥和数据库账号。
- 工号是身份识别的唯一业务键，应在接入人力系统前明确工号发放、停用和复用规则；本版本不允许复用。
- 权限管理员应按最小权限原则授予角色和客户经理业务范围，并定期审查 `sys_user_role_grant` 中的启用记录。
- 静态服务器将 `/api` 和健康检查反向代理到后端；SSE 关闭缓冲，读取超时大于 60 秒。
- 后端数据库账号应只具备所需权限；业务查询建议使用独立只读账号。
- 应用、对话和 SQL 复核日志按权限保存，不记录完整模型思考和业务结果明细。
